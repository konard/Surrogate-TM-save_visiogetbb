# save_visiogetbb
Архив форума

## Версия из PR #18 и восстановление старого архива

Пока [PR #18](https://github.com/Surrogate-TM/save_visiogetbb/pull/18) не объединён,
исправления находятся в ветке `issue-17-82b33b413f46`, а не в `main`.
Скачайте [parser.py из этой ветки](https://raw.githubusercontent.com/konard/Surrogate-TM-save_visiogetbb/issue-17-82b33b413f46/parser.py)
вместо старой копии. Например, в PowerShell из каталога со скриптом:

```powershell
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/konard/Surrogate-TM-save_visiogetbb/issue-17-82b33b413f46/parser.py" -OutFile parser.py
python parser.py --version
# ForumArchiver 2026.10.10
python parser.py -o forum_archive --repair-archive
python parser.py -o forum_archive --resume
```

`--repair-archive` исправляет шапки, подвал и ссылки на сообщения в уже
сохранённых страницах без сетевых запросов, сохраняя пути к скачанным вложениям.
Он также обновляет `posts.json` и `forum.json`. Поддерживаются старые ссылки вида
`viewtopic__p=19537.html` без якоря. Если сообщение ещё не скачано, ссылка ведёт
на исходный форум. Для докачки страниц после исправления используйте `--resume`;
он также очищает уже сохранённые страницы перед продолжением обхода.

В архиве удаляются строка «Часовой пояс» под навигационной цепочкой, иконки
«Профиль» и «Ответить с цитатой» под сообщениями, а на главной странице — всё
после списка форумов: «Удалить cookies конференции | Наша команда», нижняя
цепочка «Портал » Список форумов», «Кто сегодня был на конференции»,
«Статистика» и форма входа.

При запуске в консоли и `downloads.log` выводятся версия, полный путь к
исполняемому `parser.py`, таймауты и параметры повторов. Это позволяет обнаружить
запуск другой копии скрипта. Лог с повторением 404 и таймаутом 60 с при запуске
без параметров соответствует более старому или изменённому скрипту.

# Использование
```
# Полное архивирование (займёт много времени)
python parser.py -o forum_archive

# С ограничением количества страниц и задержкой между HTTP-запросами
python parser.py -o forum_archive --max-pages 100 --delay 0.1

# Начать с конкретного раздела
python parser.py -o forum_archive --start-url "https://visio.getbb.ru/viewforum.php?f=3"

# Подробный лог
python parser.py -o forum_archive -v
```

## Надёжность загрузки вложений

Если сервер начинает «подвешивать» соединения, парсер:

- считает зависшим запрос, который не ответил за `--read-timeout` секунд
  (по умолчанию 20 вместо прежних 60);
- не повторяет запросы с постоянными ошибками (404 и подобные);
- запоминает неудачные ссылки, поэтому одно и то же вложение не запрашивается
  заново на каждой странице, где оно упомянуто;
- делает паузу с ростом задержки, когда подряд идут зависания, чтобы
  ограничение на стороне сервера успело сброситься;
- после обхода выполняет отложенные повторные проходы по временно
  недоступным страницам и вложениям (`--retry-passes`, по умолчанию 2);
- делает не более трёх попыток скачать каждое вложение за весь запуск
  (одна во время обхода и по одной в отложенных проходах);
- страница с недоступным вложением всё равно сохраняется, а список таких
  вложений записывается в `failed_attachments.md` в виде таблицы
  «Сообщение форума | Путь к вложению»;
- ссылка на недоступное вложение ведёт на форум, а не на несуществующий
  локальный путь `./download/file.php`; `--repair-archive` исправляет такие
  ссылки и в ранее сохранённых страницах.

После шести последовательных временных ошибок одного хоста остальные
запросы к нему откладываются до следующего повторного прохода. Это ограничивает
затраты на таймауты во время перебоя; успешные запросы к другим хостам не сбрасывают
счётчик ошибок форума. Не загруженные страницы перечисляются в `failed_pages.json`.
Каждая страница запрашивается не более трёх раз за запуск. Восстановленные
вложения получают локальные ссылки в уже сохранённых HTML.

`--resume` проходит по ссылкам сохранённых страниц и загружает пропущенные
страницы, а также повторно скачивает вложения, которые не удалось загрузить в
уже сохранённых страницах. Ссылки на цитируемые сообщения (и ссылки колонки
«Последнее сообщение») переписываются на страницу с нужным якорем после обхода,
а также при остановке через Ctrl-C. Если нужного сообщения в архиве нет (например,
его страница не загрузилась во время сбоя форума), ссылка пока остаётся ведущей на
форум и станет локальной после следующего запуска с `--resume`.

```
# Более терпеливые таймауты
python parser.py -o forum_archive --read-timeout 30

# Отключить отложенные повторные проходы
python parser.py -o forum_archive --retry-passes 0

# Продолжить обход после перебоя
python parser.py -o forum_archive --resume

# Исправить ссылки на цитаты в существующем архиве без сетевых запросов
python parser.py -o forum_archive --resolve-post-links
```
