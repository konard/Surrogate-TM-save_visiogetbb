# save_visiogetbb
Архив форума

# Использование
```
# Полное архивирование (займёт много времени)
python parser.py -o forum_archive

# С ограничением количества страниц и задержкой между HTTP-запросами
python parser.py -o forum_archive --max-pages 100 --delay 0.1

# Начать с конкретного раздела
python parser.py -o forum_archive --start-url "https://visio.getbb.ru/viewforum.php?f=3"

# Подробный лог
python parser.py -o forum_archive -v
```

## Надёжность загрузки вложений

Если сервер начинает «подвешивать» соединения, парсер:

- считает зависшим запрос, который не ответил за `--read-timeout` секунд
  (по умолчанию 20 вместо прежних 60);
- не повторяет запросы с постоянными ошибками (404 и подобные);
- запоминает неудачные ссылки, поэтому одно и то же вложение не запрашивается
  заново на каждой странице, где оно упомянуто;
- делает паузу с ростом задержки, когда подряд идут зависания, чтобы
  ограничение на стороне сервера успело сброситься;
- после обхода выполняет отложенные повторные проходы по временно
  недоступным страницам и вложениям (`--retry-passes`, по умолчанию 2);
- делает не более трёх попыток скачать каждое вложение за весь запуск
  (одна во время обхода и по одной в отложенных проходах);
- страница с недоступным вложением всё равно сохраняется, а список таких
  вложений записывается в `failed_attachments.md` в виде таблицы
  «Сообщение форума | Путь к вложению».

После шести последовательных временных ошибок одного хоста остальные
запросы к нему откладываются до следующего повторного прохода. Это ограничивает
затраты на таймауты во время перебоя; успешные запросы к другим хостам не сбрасывают
счётчик ошибок форума. Не загруженные страницы перечисляются в `failed_pages.json`.
Каждая страница запрашивается не более трёх раз за запуск. Восстановленные
вложения получают локальные ссылки в уже сохранённых HTML.

`--resume` проходит по ссылкам сохранённых страниц и загружает пропущенные
страницы. Ссылки на цитируемые сообщения переписываются на страницу с нужным
якорем после обхода, а также при остановке через Ctrl-C. Если нужного сообщения
в архиве нет, ссылка пока остаётся ведущей на форум.

```
# Более терпеливые таймауты
python parser.py -o forum_archive --read-timeout 30

# Отключить отложенные повторные проходы
python parser.py -o forum_archive --retry-passes 0

# Продолжить обход после перебоя
python parser.py -o forum_archive --resume

# Исправить ссылки на цитаты в существующем архиве без сетевых запросов
python parser.py -o forum_archive --resolve-post-links
```
